# پیشرفته

[بازگشت به README](../../README.fa.md) · [English](../en/advanced.md)

برای استفادهٔ عادی به این صفحه نیاز نداری.

## خواندن اسکریپت پیش از اجرا

آن را دانلود کن، بخوان و بعد اجرا کن:

</div>

```bash
curl -fsSL https://github.com/MohZeh/Darban-OVPN/releases/download/v1.0.0-rc.2/get.sh -o get.sh
```

```bash
sudo bash get.sh
```

<div dir="rtl">

دستور یک‌خطی عمداً `curl` را داخل `sudo` اجرا می‌کند. در شکل `curl ... | sudo bash`، sudo ورودی را از pipe می‌خواند و در اوبونتو دستور را در ترمینال جداگانهٔ خودش اجرا می‌کند؛ برای همین کلیدهایی که می‌زنی هیچ‌وقت به پرسش‌های نصب نمی‌رسند. `get.sh` روی سرور تازه این شکل را تشخیص می‌دهد و پیش از دانلود هر چیزی می‌ایستد.

`get.sh` نسخه را دانلود و با `SHA256SUMS` مقایسه می‌کند و اگر یکی نباشند، چیزی اجرا نمی‌شود. هش از همان نسخه می‌آید، پس دانلود خراب را تشخیص می‌دهد، نه حساب هک‌شده را.

## نصب نسخهٔ مشخص

از آدرس همان نسخه استفاده کن. خودش همان نسخه را نصب می‌کند:

</div>

```bash
sudo bash -c 'curl -fsSL https://github.com/MohZeh/Darban-OVPN/releases/download/v1.0.0-rc.2/get.sh | bash'
```

<div dir="rtl">

برای برگشت به نسخهٔ قدیمی‌تر روی سرور نصب‌شده، نام آن را بگو:

</div>

```bash
sudo bash -c 'curl -fsSL https://github.com/MohZeh/Darban-OVPN/releases/download/v1.0.0-rc.2/get.sh | bash -s -- --version v1.0.0-rc.1'
```

<div dir="rtl">

## نصب بدون پرسش

</div>

```bash
sudo bash -c 'curl -fsSL https://github.com/MohZeh/Darban-OVPN/releases/download/v1.0.0-rc.2/get.sh | bash -s -- --yes --host vpn.example.com --port 1194'
```

<div dir="rtl">

| گزینه | معنی |
|---|---|
| `--yes` | چیزی نپرس و پیش‌فرض‌ها را بردار |
| `--host NAME\|IP` | آدرسی که کلاینت‌ها به آن وصل می‌شوند |
| `--port N` | پورت UDP |
| `--subnet A.B.C.0` | شبکهٔ VPN، یک `/24` خصوصی |
| `--dns "IP [IP]"` | DNS کلاینت‌ها |
| `--split-tunnel` | فقط ترافیک VPN از سرور رد شود |
| `--open-ufw` | قوانین `ufw` را اضافه کن. با `--yes` به‌تنهایی `ufw` تغییر نمی‌کند |
| `--install-kernel` | کرنل Virtual HWE را نصب کن، حتی اگر کرنل فعلی ماژول `ovpn` را دارد |

## نصب چه کارهایی می‌کند

- مخزن رسمی OpenVPN (کانال stable) را اضافه می‌کند و `openvpn`، `easy-rsa`، `socat` و `nftables` را نصب می‌کند.
- اگر کرنل فعلی ماژول `ovpn` نداشته باشد، `linux-image-virtual-hwe-24.04` یا `linux-image-virtual-hwe-26.04` را متناسب با سیستم و بدون بسته‌های پیشنهادی نصب می‌کند. اگر `apt` بستهٔ firmware یا گرافیکی برنامه‌ریزی کند، نصب متوقف می‌شود. container به کرنل نیاز ندارد.
- CA را در `/root/pki` و گواهی سرور را با اعتبار ۱۰ سال می‌سازد.
- `/etc/openvpn/server/server.conf` را می‌نویسد، IPv4 forwarding را روشن می‌کند و NAT فقط برای VPN را در جدول nftables جدا اضافه می‌کند.
- کلاینت‌ها را از هم جدا نگه می‌دارد: از راه سرور به هم و به سرویس metadata ارائه‌دهندهٔ ابری در `169.254.169.254` نمی‌رسند. به شبکه‌های خصوصی دیگری که سرور به آن‌ها دسترسی دارد هنوز می‌رسند.
- OpenVPN را راه می‌اندازد و جزئیات را در `/var/log/darban-setup.log` می‌نویسد.

اگر کرنل اضافه شود، کرنل فعلی به‌عنوان پشتیبان می‌ماند و Reboot خودکار انجام نمی‌شود. VPN همان لحظه بدون [DCO](glossary.md#dco) کار می‌کند.

آدرس از کارت شبکه خوانده می‌شود. پشت NAT، از `api.ipify.org` و بعد `ifconfig.me` پرسیده می‌شود، که آدرس این سرور را می‌بینند.

| پیش‌فرض | مقدار |
|---|---|
| شبکهٔ VPN | اولین `/24` آزاد از `10.8.0.0` |
| مسیر ترافیک | همهٔ ترافیک IPv4 کلاینت |
| DNS کلاینت | `1.1.1.1` و `8.8.8.8` |

## سروری که از قبل OpenVPN دارد

اگر `/etc/openvpn/server/server.conf` وجود داشته باشد، نصب سرور رد می‌شود و نصب‌کننده تنظیمات OpenVPN را تغییر نمی‌دهد و آن را ری‌استارت نمی‌کند. این ساختار لازم است:

- OpenVPN 2.7 با `udp4` و دقیقاً یک `tls-crypt` که از `/etc/openvpn/server/tls-crypt.key` استفاده کند
- Easy-RSA 3 در `/usr/share/easy-rsa/easyrsa`، با PKI در `/root/pki` و کلید CA بدون رمز
- ثبت گواهی سرور در `index.txt` همان PKI
- `crl-verify /etc/openvpn/server/crl.pem` با یک CRL معتبر
- سرویس فعال `openvpn-server@server.service`

اگر بررسی‌ای رد شود، نصب‌کننده پیش از نصب متوقف می‌شود و دلیل را می‌گوید. روی چنین سروری **Remove everything** رد می‌شود و تغییر شبکهٔ VPN هم مجاز نیست، چون NAT آن را این ابزار مدیریت نمی‌کند.

برای قطع نشست تکی، یک management socket محلی اضافه کن و `socat` را نصب کن:

</div>

```text
management /run/openvpn-server/darban.sock unix
```

## تنظیمات پیشرفته

**Settings › Advanced** را باز کن. گزینه‌های ۱ تا ۶ فایل `server.conf` را تغییر می‌دهند و OpenVPN را ری‌استارت می‌کنند: کاربران متصل برای چند ثانیه قطع می‌شوند و خودشان دوباره وصل می‌شوند.

| # | تنظیم | توضیح |
|---|---|---|
| ۱ | Traffic routing | **Full tunnel** همهٔ IPv4 کلاینت را از سرور می‌گذراند؛ **split tunnel** فقط شبکهٔ VPN را. رفتن به full اگر DNS تنظیم نباشد، DNS پیش‌فرض را اضافه می‌کند. Full tunnel به NAT روی سرور نیاز دارد |
| ۲ | DNS for clients | یک یا دو IPv4. در split tunnel استفاده نمی‌شود و کلاینت‌ها DNS خودشان را نگه می‌دارند |
| ۳ | VPN network | یک `/24` خصوصی که به `.0` ختم شود و با مسیر موجود تداخل نداشته باشد. NAT هم همراه آن تغییر می‌کند. اگر این ابزار NAT را نساخته باشد رد می‌شود. آدرس‌های ثابت `client-config-dir` یا `ifconfig-pool-persist` به‌روز نمی‌شوند |
| ۴ | Data ciphers | `AES-256-GCM`، `AES-128-GCM`، `CHACHA20-POLY1305`، جدا با `:`. بقیه DCO را خاموش می‌کنند. کلاینت بدون رمز مشترک باید پروفایل جدید بگیرد |
| ۵ | Keepalive | فاصلهٔ ping و مهلت به ثانیه. مهلت باید دست‌کم دو برابر فاصله باشد |
| ۶ | Log detail | از `0` تا `6`؛ `3` حالت عادی است. `4` به بالا برای عیب‌یابی است و ممکن است اطلاعات خصوصی را ثبت کند |
| ۷ | Download access | آدرس، پورت و کاربر SSH در دستورهای `scp` و `sftp`؛ بدون ری‌استارت |
| ۸ | New client lifetime | تعداد روز گواهی کلاینت‌های جدید؛ `0` یعنی پیش‌فرض Easy-RSA؛ بدون ری‌استارت |
| ۹ | Share link port | پورت TCP لینک موقت؛ بدون ری‌استارت |

**تغییر چطور اعمال می‌شود:** تأیید می‌کنی، از `server.conf` کنار خودش پشتیبان گرفته می‌شود (پنج نسخهٔ آخر می‌مانند) و OpenVPN ری‌استارت می‌شود. اگر پورت UDP تا ۵ ثانیه برنگردد، فایل قبلی برمی‌گردد و OpenVPN دوباره اجرا می‌شود. اگر این هم شکست بخورد، پیام فوری نمایش داده می‌شود. این بررسی محلی است و ثابت نمی‌کند کلاینت‌ها از اینترنت به سرور می‌رسند.

`/etc/darban/config` تنظیمات ابزار را نگه می‌دارد و فقط به‌صورت داده خوانده می‌شود، نه اجرا.

</div>

```text
DOWNLOAD_SSH_HOST=203.0.113.10
DOWNLOAD_SSH_PORT=22
DOWNLOAD_SSH_USER=root
CLIENT_CERT_DAYS=825
LINK_PORT=443
UPDATE_CHECK=no
```

<div dir="rtl">

`UPDATE_CHECK=no` اعلان روزانهٔ نسخهٔ جدید را خاموش می‌کند؛ **Setup › Daily update notice** هم همین کار را می‌کند. ابزار هرگز خودش به‌روزرسانی را نصب نمی‌کند.

## پورت‌های فایروال

| پورت | کاربرد |
|---|---|
| پورت UDP انتخابی | کلاینت‌های VPN |
| TCP 443، 8443 یا 9443 | لینک موقت؛ اولین پورت آزاد نگه داشته می‌شود |
| TCP 80، برای چند لحظه | فقط برای گواهی Let's Encrypt، هنگام گرفتن و در هر تمدید: برای دامنه حدود هر ۶۰ روز، و برای هر گواهی شش‌روزهٔ تازهٔ آدرس IP |

## فهرست مسدودها (CRL)

OpenVPN برای هر اتصال جدید CRL را می‌خواند. تایمر روزانه وقتی ۶۰ روز یا کمتر مانده باشد، یا فایل منتشرشده نامعتبر باشد، آن را تمدید می‌کند.

</div>

```bash
sudo darban-crl-maintain --check
```

```bash
sudo journalctl -u darban-crl.service -n 20 --no-pager
```

<div dir="rtl">

### ابطالی که کامل نشده

اگر گواهی در CA باطل شود ولی CRL منتشر نشود، **آن کلاینت هنوز می‌تواند وصل شود**. منو، فهرست و عیب‌یابی نام او را تا رفع مشکل نشان می‌دهند. بعد از رفع علت، **Maintenance › Repair CRL** یا `sudo darban repair-crl` را اجرا کن. این کار CRL را منتشر می‌کند، پروفایل باقی‌مانده را حذف می‌کند و به نشست فعال رسیدگی می‌کند.

<a id="old-ca-backup"></a>

### بازگرداندن پشتیبان قدیمی CA

برگرداندن `index.txt` قدیمی می‌تواند کلاینت‌های باطل‌شده را دوباره معتبر کند. ابزار این را خطا می‌داند و انتشار CRL‌ای را که گواهی باطل‌شدهٔ منقضی‌نشده را حذف کند رد می‌کند؛ حتی در تایمر و ترمیم. **`index.txt` فعلی را برگردان.** فقط اگر واقعاً می‌خواهی ابطال برگردد:

</div>

```bash
sudo darban-crl-maintain --renew --allow-crl-shrink
```

<div dir="rtl">

این محافظت به CRL منتشرشده تکیه دارد. اگر `index.txt` و `crl.pem` هر دو از یک پشتیبان قدیمی برگردند، ابزار تناقضی نمی‌بیند و ابطال‌های بعدی از دست می‌روند. بعد از هر بازیابی، فهرست باطل‌شده‌ها را با سوابق خودت مقایسه کن.

## گواهی‌ها

فقط CRL خودکار تمدید می‌شود. منو ۳۰ روز پیش از انقضای گواهی CA یا سرور هشدار می‌دهد و تمدید آن‌ها کار دستی با Easy-RSA است. برای گواهی کلاینتی که منقضی می‌شود، کلاینت جدید لازم است.

<a id="backup"></a>

## پشتیبان

یک نسخهٔ **رمزگذاری‌شده** از این مسیرها را بیرون از سرور نگه دار. این‌ها کلید خصوصی CA را دارند. هرگز آن‌ها را به اشتراک نگذار یا در مخزن قرار نده.

</div>

```text
/root/pki
/etc/openvpn/server
/etc/darban
```

<a id="removal"></a>

## حذف چه می‌کند

| گزینه | حذف می‌کند | نگه می‌دارد |
|---|---|---|
| **Setup › Uninstall this tool only** | ابزار، تایمر و لینک‌های باز | OpenVPN، PKI، CRL، `server.conf`، پروفایل‌ها، تنظیمات |
| **Setup › Remove everything** | ابزار، OpenVPN، CA، پروفایل‌ها، NAT، مخزن، بسته‌ها و certbot‌ای که نصب اضافه کرده، و گواهی‌ای که گرفته | کرنل Virtual HWE مگر به انتخاب تو، پشتیبان اختیاری، و آنچه از قبل بوده: فایل‌های دیگر پوشهٔ پروفایل‌ها، قانون‌های `ufw`، و فایل‌های مخزن که برگردانده می‌شوند |

**بعد از Uninstall دیگر چیزی CRL را تمدید نمی‌کند.** خودت پیش از انقضا آن را تمدید کن، وگرنه OpenVPN ممکن است کلاینت‌ها را رد کند.

**بعد از Remove everything همهٔ فایل‌های `.ovpn` از کار می‌افتند،** حتی اگر OpenVPN را دوباره نصب کنی. فقط برگرداندن پشتیبان، CA قدیمی و همراه آن پروفایل‌های قدیمی را برمی‌گرداند. نسخه‌های روی دستگاه‌ها پاک نمی‌شوند، فقط دیگر وصل نمی‌شوند. پیش از حذف، پشتیبان پیشنهاد می‌شود و پیش‌فرض همان است. این گزینه فقط روی سروری کار می‌کند که نصب آن را ساخته باشد. بسته‌ها فقط وقتی حذف می‌شوند که نصب آن‌ها را اضافه کرده و چیز دیگری به آن‌ها نیاز نداشته باشد. کرنل در حال اجرا هرگز حذف نمی‌شود. بستن پورت‌ها در فایروال ارائه‌دهنده با خودت است.

اگر نصب نیمه‌کاره مانده باشد، با این دستور برگردانده می‌شود:

</div>

```bash
sudo bash /usr/local/lib/darban/remove-server.sh --yes
```
