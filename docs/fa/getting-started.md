# شروع کار

[بازگشت به README](../../README.fa.md) · [English](../en/getting-started.md)

این راهنما از یک سرور تازه تا اولین کاربر متصل پیش می‌رود. در هر گام نوشته شده است که چه چیزی باید ببینید و اگر چیز دیگری دیدید، چه کنید. معنی اصطلاح‌ها در [واژه‌نامه](glossary.md) آمده است.

## گام ۱: یک سرور تهیه کنید

یک VPS تازه با **Ubuntu 24.04 یا 26.04** از هر ارائه‌دهنده‌ای تهیه کنید. نوع سرور را `amd64` انتخاب کنید؛ پشتیبانی از `arm64` هنوز در مرحلهٔ آزمایش است.

**آنچه لازم دارید:** آدرس IP سرور، و امکان ورود با `root` یا با کاربری که دسترسی `sudo` دارد.

**اگر این اطلاعات را ندارید:** به پنل ارائه‌دهنده سر بزنید. بیشتر ارائه‌دهنده‌ها آدرس و اطلاعات ورود را در صفحهٔ همان سرور نشان می‌دهند.

## گام ۲: به سرور وصل شوید

روی کامپیوتر خود ترمینال را باز کنید و با دستور زیر وصل شوید. به‌جای این آدرس، آدرس سرور خود را بنویسید:

</div>

```bash
ssh root@203.0.113.10
```

<div dir="rtl">

**نتیجهٔ مورد انتظار:** خط فرمان سرور نمایش داده می‌شود.

**اگر وصل نشد:** آدرس و نام کاربری را در پنل ارائه‌دهنده بررسی کنید. مستقیم وصل شوید، نه از راه VPNی که قرار است روی همین سرور راه بیندازید.

<a id="step-3"></a>
## گام ۳: دستور نصب را اجرا کنید

</div>

```bash
sudo bash -c 'curl -fsSL https://github.com/MohZeh/Darban-OVPN/releases/download/v1.0.0-rc.4/get.sh | bash'
```

<div dir="rtl">

**نتیجهٔ مورد انتظار:** `Step 1 of 2: Server address`

**اگر این را نمی‌بینید:**
- `curl: command not found`: دستور `sudo apt update && sudo apt install -y curl` را اجرا کنید و سپس دستور نصب را دوباره بزنید.
- `Started as "curl ... | sudo bash"`: دستور به شکل دیگری وارد شده است. دستور بالا را دقیقاً همان‌طور که هست کپی و دوباره اجرا کنید. چیزی نصب نشده است.
- `curl: (22)` و `404`: آن نسخه منتشر نشده است. دستور نصب یک نسخهٔ منتشرشده را از صفحهٔ [Releases](https://github.com/MohZeh/Darban-OVPN/releases) بردارید.

## گام ۴: به پرسش‌ها پاسخ دهید

هر پرسش یک پیشنهاد نشان می‌دهد. **برای پذیرفتن آن Enter بزنید.**

1. **Server address:** Enter بزنید. داشتن دامنه اختیاری است. با دامنه یا IP عمومی، ابزار می‌تواند برای لینک موقت گواهی معتبر بگیرد تا لینک بدون هشدار مرورگر باز شود.
2. **VPN port:** Enter بزنید. پورت پیشنهادی از میان پورت‌های آزاد به‌طور تصادفی انتخاب می‌شود و 1194، پورت رایج OpenVPN، نیست. این کار جای فایروال یا رمزنگاری را نمی‌گیرد.
3. **Install this server?** روی **Install now** Enter بزنید.

تا پیش از پاسخ سوم چیزی نصب نمی‌شود؛ تا آن زمان ابزار فقط فهرست بسته‌ها را به‌روز می‌کند. برای دیدن جزئیات کامل نصب، `2` را بزنید و سپس روی **Show details** Enter بزنید.

**نتیجهٔ مورد انتظار:** پنج مرحلهٔ کوتاه، و در پایان `Your VPN server is ready`.

**اگر نصب کامل نشد:** صفحه آخرین خط‌های لاگ را نشان می‌دهد. همان دستور نصب را دوباره اجرا کنید تا از همان‌جا ادامه دهد. برای برگرداندن همه‌چیز، دستوری را اجرا کنید که روی صفحه نمایش داده شده است.

## گام ۵: پورت VPN را در فایروال ارائه‌دهنده باز کنید

بسیاری از ارائه‌دهنده‌ها در پنل خود فایروال دارند، معمولاً با نام **Firewall**، **Security Group** یا **Network Rules**. این ابزار آن فایروال را نمی‌بیند و نمی‌تواند تغییرش دهد.

قانونی اضافه کنید که **ورود UDP روی پورت VPN** را مجاز کند. ابزار این پورت را زیر `Your VPN server is ready` با عنوان `Port` نشان می‌دهد.

**اگر ارائه‌دهنده چنین فایروالی ندارد:** به گام بعد بروید.

## گام ۶: اولین کلاینت را بسازید

هر کلاینت یک پروفایل اتصال با گواهی مخصوص خود است، معمولاً برای یک نفر یا یک دستگاه. ابزار بلافاصله پس از نصب این پرسش‌ها را می‌پرسد:

1. **Create your first client now?** Enter بزنید.
2. **Client name:** با Enter نام `client1` انتخاب می‌شود. می‌توانید نامی مانند `ali-phone` هم بنویسید.
3. **How will the client get this profile?** برای **Temporary link** Enter بزنید.
4. **Get a free Let's Encrypt certificate?** این پرسش فقط روی آدرس عمومی می‌آید. پورت TCP 80 را برای چند لحظه در فایروال ارائه‌دهنده باز کنید و برای **Yes, get a certificate** Enter بزنید؛ اگر گواهی صادر شود، لینک بدون هشدار مرورگر باز می‌شود. اگر روی سرور از قبل گواهی معتبری برای همین آدرس باشد، ابزار ابتدا همان را پیشنهاد می‌دهد و Enter از آن استفاده می‌کند. تا گواهی معتبر نداشته باشید، این پرسش با هر لینک دوباره می‌آید. بخش [هشدار مرورگر](sharing.md#browser-warning) را ببینید.
5. **Lock the private key with a password?** برای بدون رمز Enter بزنید. اینکه رمز چه زمانی مفید است، در بخش [رمز کلید خصوصی](sharing.md#a-password-on-the-key) آمده است.
6. **At most, how long should the link work?** برای ۲۴ ساعت Enter بزنید. معمولاً لینک زودتر تمام می‌شود: حدود ۱۰ ثانیه پس از اینکه اتصالی با این پروفایل دیده شود.

**نتیجهٔ مورد انتظار:** لینکی که با `https://` شروع می‌شود، همراه با پورت TCP آن.

**اگر لینک ساخته نشد:** بخش [لینک باز نمی‌شود](troubleshooting.md#link-fails) را ببینید.

این پورت TCP را هم مانند گام ۵ در فایروال ارائه‌دهنده باز کنید. ابزار پورت را کنار لینک نشان می‌دهد.

## گام ۷: لینک را بفرستید

لینک را با هر پیام‌رسانی بفرستید؛ پیش‌نمایش پیام‌رسان آن را مصرف نمی‌کند. لینک تا پایان مهلتش، یا تا وقتی که اتصالی با این پروفایل دیده شود، کار می‌کند و تا آن زمان گیرنده می‌تواند دوباره بازش کند.

اگر لینک گواهی معتبر نداشته باشد، مرورگر هنگام باز کردن آن هشدار امنیتی نشان می‌دهد. در این حالت ابزار یک متن کوتاه برای گیرنده نشان می‌دهد؛ آن را همراه لینک بفرستید. متن فارسی همین پیام در بخش [هشدار مرورگر](sharing.md#browser-warning) آمده است. اگر روی کلید رمز گذاشته‌اید، رمز را از راه دیگری بفرستید، مثلاً با پیامک یا تماس تلفنی.

## گام ۸: دستگاه را وصل کنید

گیرندهٔ لینک راهنمای [اتصال دستگاه](connect-devices.md) را دنبال می‌کند.

## گام ۹: اتصال را بررسی کنید

ابزار منتظر اتصال می‌ماند و این پیام را نشان می‌دهد:

</div>

```text
✓ client1 is connected from 198.51.100.7. The server and your provider's firewall let the VPN through.
```

<div dir="rtl">

این پیام نشان می‌دهد که دستگاه از فایروال ارائه‌دهنده گذشته و به سرور رسیده است. وصل بودن اینترنت روی خود دستگاه را نشان نمی‌دهد؛ برای آن، روی همان دستگاه بخش [بررسی اتصال](connect-devices.md#check-it-works) را انجام دهید.

**اگر این پیام نیامد:** پس از چند دقیقه با Enter انتظار را تمام کنید و بخش [کلاینت وصل نمی‌شود](troubleshooting.md#cannot-connect) را ببینید.

## گام ۱۰: اگر ابزار خواست، سرور را Reboot کنید

اگر نصب یک کرنل اضافه کرده باشد، ابزار پیشنهاد می‌دهد هر زمان که مناسب بود، سرور را یک بار Reboot کنید. VPN بدون Reboot هم کار می‌کند، ولی پس از آن سریع‌تر است.

</div>

```bash
sudo reboot
```

<div dir="rtl">

## باز کردن دوبارهٔ منو

با بستن منو یا قطع SSH، VPN همچنان کار می‌کند. برای مدیریت دوبارهٔ سرور، مانند گام ۲ با SSH وصل شوید و این دستور را اجرا کنید:

</div>

```bash
sudo darban
```

<div dir="rtl">

منو باز می‌شود. این تنها دستوری است که لازم است به یاد داشته باشید؛ ابزار هم هر بار که منو را می‌بندید، آن را دوباره نشان می‌دهد.
