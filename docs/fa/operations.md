# نگهداری

[بازگشت به README](../../README.fa.md) · [English](../en/operations.md)

## عیب‌یابی

**Maintenance › Diagnostics** یا `sudo darban status` سرویس، پورت، گواهی‌ها، CRL، تایمر، forwarding، NAT و آدرس را بررسی می‌کند.

## CRL

OpenVPN برای هر اتصال جدید CRL را می‌خواند. تایمر روزانه وقتی ۶۰ روز یا کمتر مانده باشد، یا فایل منتشرشده نامعتبر باشد، آن را تمدید می‌کند.

</div>

```bash
sudo darban-crl-maintain --check
sudo journalctl -u darban-crl.service -n 20 --no-pager
```

<div dir="rtl">

### ابطالی که کامل نشده

اگر گواهی در CA باطل شود ولی CRL منتشر نشود، **آن کلاینت هنوز می‌تواند وصل شود**. سرصفحه، فهرست و عیب‌یابی نام او را تا رفع مشکل نشان می‌دهند. بعد از رفع علت، **Maintenance › Repair CRL** یا این دستور را اجرا کن:

</div>

```bash
sudo darban repair-crl
```

<div dir="rtl">

این کار CRL را منتشر می‌کند، پروفایل باقی‌مانده را حذف می‌کند و به نشست فعال رسیدگی می‌کند.

### بازگرداندن پشتیبان قدیمی CA

برگرداندن `index.txt` قدیمی می‌تواند کلاینت‌های باطل‌شده را دوباره معتبر کند. ابزار این را خطا می‌داند و انتشار CRL‌ای را که گواهی باطل‌شدهٔ منقضی‌نشده را حذف کند رد می‌کند؛ حتی در تایمر و ترمیم. **`index.txt` جدید را برگردان.** فقط اگر واقعاً می‌خواهی ابطال برگردد:

</div>

```bash
sudo darban-crl-maintain --renew --allow-crl-shrink
```

<div dir="rtl">

این محافظت به CRL منتشرشده تکیه دارد. اگر `index.txt` و `crl.pem` هر دو از یک پشتیبان قدیمی برگردند، ابزار تناقضی نمی‌بیند و ابطال‌های بعدی از دست می‌روند. بعد از هر بازیابی، فهرست باطل‌شده‌ها را با سوابق خودت مقایسه کن.

## گواهی‌ها

فقط CRL خودکار تمدید می‌شود. سرصفحه ۳۰ روز پیش از انقضای گواهی CA یا سرور هشدار می‌دهد. تمدید آن‌ها کار دستی با Easy-RSA است.

## پشتیبان

یک نسخهٔ **رمزگذاری‌شده** از این مسیرها را بیرون از سرور نگه دار:

</div>

```text
/root/pki
/etc/openvpn/server
/etc/darban
```

<div dir="rtl">

این‌ها کلید خصوصی CA را دارند. هرگز آن‌ها را به اشتراک نگذار یا در مخزن قرار نده.

## به‌روزرسانی

منو حداکثر روزی یک بار و در پس‌زمینه نسخهٔ پایدار جدید را اعلام می‌کند و خودش چیزی نصب نمی‌کند. **Setup › Check for updates** یا `sudo darban update` تغییرات نسخه را نشان می‌دهد و تأیید می‌گیرد. فقط خود ابزار عوض می‌شود؛ OpenVPN ری‌استارت نمی‌شود و کلاینت‌ها، PKI و CRL دست نمی‌خورند.

نسخهٔ قبلی نگه داشته می‌شود و **Setup › Restore previous version** به آن برمی‌گردد.

نسخهٔ پیش از انتشار هرگز خودکار پیشنهاد نمی‌شود. برای نصب آن:

</div>

```bash
curl -fsSL https://github.com/MohZeh/darban-ovpn/releases/download/v1.0.0-rc.1/get.sh | sudo bash
```

## حذف

| گزینه | حذف می‌کند | نگه می‌دارد |
|---|---|---|
| **Setup › Uninstall this tool only** | ابزار، تایمر و لینک‌های باز | OpenVPN، PKI، CRL، `server.conf`، پروفایل‌ها، تنظیمات |
| **Setup › Remove everything** | ابزار، OpenVPN، CA، پروفایل‌ها، NAT، مخزن و بسته‌هایی که نصب اضافه کرده | کرنل Virtual HWE، مگر به انتخاب تو، و پشتیبان اختیاری |

**بعد از Uninstall دیگر چیزی CRL را تمدید نمی‌کند.** خودت پیش از انقضا آن را تمدید کن، وگرنه OpenVPN ممکن است کلاینت‌ها را رد کند.

**بعد از Remove everything همهٔ فایل‌های `.ovpn` برای همیشه از کار می‌افتند،** حتی اگر OpenVPN را دوباره نصب کنی. پیش از حذف، نسخهٔ پشتیبان پیشنهاد می‌شود و پیش‌فرض همان است. این گزینه فقط روی سروری کار می‌کند که `server-setup.sh` آن را ساخته باشد. بسته‌ها فقط وقتی حذف می‌شوند که نصب آن‌ها را اضافه کرده و چیز دیگری به آن‌ها نیاز نداشته باشد. کرنل در حال اجرا هرگز حذف نمی‌شود. بستن پورت‌ها در فایروال ارائه‌دهنده با خودت است.

اگر نصب سرور نیمه‌کاره مانده باشد، از پوشهٔ آرشیو استخراج‌شده اجرا کن:

</div>

```bash
sudo bash setup/remove-server.sh --yes
```

## مشکلات رایج

| نشانه | بررسی |
|---|---|
| کلاینت وصل نمی‌شود | پورت UDP در فایروال ارائه‌دهنده، بعد `sudo darban status` |
| وصل است ولی اینترنت ندارد | forwarding و NAT در Diagnostics. با Docker ممکن است FORWARD روی DROP باشد. با `ufw` باید forwarding از `tun0` مجاز باشد |
| لینک باز نمی‌شود | پورت TCP آن در فایروال ارائه‌دهنده، بعد `sudo journalctl -u darban-links.service -n 30 --no-pager` |
| هشدار مرورگر برای لینک | گواهی خودامضاست. از hostname و Let's Encrypt استفاده کن |
| «عملیات دیگری در حال اجراست» | تایمر CRL قفل را گرفته؛ یک دقیقه بعد دوباره امتحان کن |
| DCO بارگذاری نشده | با کرنل Virtual HWE دوباره Reboot کن. در container به میزبان بستگی دارد |

هنگام گزارش مشکل، این خروجی را بفرست و **هرگز** کلید خصوصی یا فایل `.ovpn` را نفرست:

</div>

```bash
sudo journalctl -u openvpn-server@server -u darban-links -n 50 --no-pager
```
